# Public-content review

1. Use only generic educational information explicitly supplied and approved for public release.
2. Inspect every staged file and filename. Exclude identifying facts, institution-specific information, and source records.
3. Run the privacy checker before every commit. Resolve each finding by removing the information, not suppressing the check.
4. Confirm the target repository is public and the intended content belongs there. Personalized work belongs in a separate private repository.
5. Require the Privacy check for pull request merges through GitHub repository rules.

The repository starts empty. No educational claims, lesson sequences, or progress values should be invented to populate it.
